Re-analysis, 2026-11-14 — read this first. The original conclusions below ("the signal lever flips Elo from −21 to +28; the draw cycle is primarily a signal problem") do not survive a closer look:

  1. Confound. Each network was evaluated with the search it trained under, so the assisted network's Elo was measured with the material heuristic in its search and the baseline's without. Arms were never compared under the same search.
  2. No starting-network reference. All three arms trained from the same seed-42 initial network. Rebuilt and evaluated under the same settings, it scores 0 (95% CI −31, +31) against random with material_weight = 0 and −10 (−31, +10) with 0.30 (tools/no_learning_control.py, data). The heuristic on its own does not beat random.
  3. No intervals. A 50-game match against random is about ±40 Elo at 95%, and untrained networks alone span −7 to +120 Elo across init seeds (data).

Change against the starting network, pooling each arm's five checkpoints (250 games):

Arm Trained, pooled Starting network Change (95% CI)
baseline −22 (−38, −7) 0 (w = 0) −22 (−56, +12)
scaled (10×) +10 (−8, +28) 0 (w = 0) +10 (−26, +45)
assisted +21 (+1, +41) −10 (w = 0.30) +31 (+3, +60)
  1. Draw rule (found later the same day). Games ended as soon as a repetition could be claimed, which python-chess allows when the side to move merely has a repeating move available. Every "REP" count below includes games that ended before anyone repeated; the search also scored those positions as draws. All arms shared the rule, so comparisons hold, but the rates are inflated. The rule is fixed; see technical report §5.5.

What holds: the draw cycle in self-play (the termination tables in §A are unaffected), and a small, marginal gain for the assisted arm over its own start, from one training seed. Neither unassisted arm measurably changed strength. The repo assumes the code was unchanged between this run and the first commit (2026-07-18), which is when history begins.

Headline results#

The driver's two headline metrics are the self-play non-decisive rate (fraction of games not ending in checkmate) and Elo vs. random. "Non-decisive rate" below is the final iteration's rate (the end-of-training state); the aggregate over all of a stage's games is given alongside because for the baseline the two differ sharply (see §A).

Experiment A — compute scaling (material w = 0 in both)#

Run Total games Sims/move Non-decisive (final iter / all games) Elo vs random
baseline 100 100 100% / 92% −21
scaled 1,000 160 92% / 88% −7

Result. 10× the self-play produces more checkmates in aggregate (8/100 = 8% → 120/1000 = 12%), but the cycle is not broken. The Elo difference (−21 → −7 on the final 50-game matches) is well inside the ±40 Elo noise of a single match; against the starting network the scaled arm's change is +10 (95% CI −26, +45).

Experiment B — self-play signal at fixed compute (same budget as baseline)#

Run Total games Sims/move Material w Non-decisive (final iter / all games) Elo vs random
baseline 100 100 0.00 100% / 92% −21
assisted 100 100 0.30 70% / 81% +28

Result. Blending a 0.30 material term into self-play leaf evaluation — at the same compute as the baseline — drops the final-iteration non-decisive rate to 70% and raises the aggregate checkmate count to 19/100. (The heuristic is active during self-play, so some of those checkmates come from it directly.) The Elo comparison with the baseline is confounded, because the two were evaluated with different searches; against its own starting network under the same search, the assisted arm gained +31 Elo (95% CI +3, +60).

Reading the two together#

Only the assisted arm shows a measurable strength gain over its starting point, and only just. This run cannot rank the two levers: one training seed per arm, and the arms differ by less than seed-to-seed variation.

C. Training loss#

(The loss figure previously shown here could not be traced to this run: it has 12 iterations, and none of the three arms has 12. It was removed; only the start and end values below were transcribed.)

Total loss = policy cross-entropy + value MSE. Start (iter 1) → end (final iter):

Stage Policy loss (start → end) Value loss (start → end) Total (start → end)
baseline 4.54 → 0.81 0.092 → 0.006 4.63 → 0.81
scaled 4.02 → 0.96 0.164 → 0.012 4.19 → 0.97
assisted 4.37 → 0.69 0.101 → 0.023 4.47 → 0.71

Policy loss falls sharply in every stage — the network readily learns to imitate its own MCTS visit distribution. The value loss is tiny from the start and shrinks toward ≈0.01: with almost every game drawn, the outcome target z ≈ 0 nearly everywhere, so the value head has almost nothing to fit. That collapse is the draw-cycle signature (technical report §6), not a training success.

Key findings#

  1. The draw cycle is real and self-reinforcing. At baseline compute the network scores a few accidental mates in iters 1–2, then 100% of self-play games end in threefold repetition from iter 3 on, and the value loss collapses toward 0.
  2. 10× compute does not break it. Aggregate checkmates rise from 8% to 12%; the non-decisive rate stays in the high 80s/90s, and strength against random is indistinguishable from the starting network (+10, 95% CI −26, +45).
  3. The material assist keeps decisive games in self-play (19% checkmates, final iteration 30%) and is the only arm with a measurable gain over its start: +31 Elo (95% CI +3, +60), from a single training seed.
  4. The original headline is withdrawn. "Signal, not compute: −21 → +28" compared arms evaluated under different searches, without a starting-network reference or intervals (see the re-analysis note at the top).
  5. What would settle it: three training seeds per arm, every network also evaluated with material_weight = 0, and the combined arm. run_experiment.py --seed N now writes each seed to its own directory and evaluates every arm both ways.

Reproducibility#

# All three stages on a GPU (this run):
python run_experiment.py --device cuda

# Fast pipeline check on CPU (~1–2 min, results not meaningful):
python run_experiment.py --quick

Config used (from config.py; stages differ only in iterations/games/sims and the self-play material weight noted above):

  • Network: num_residual_blocks = 4, num_channels = 64
  • Search: c_puct = 1.5, dirichlet_alpha = 0.3, dirichlet_epsilon = 0.25
  • Self-play: temperature_moves = 15, max_moves = 200
  • Training: epochs_per_iteration = 4, batch_size = 64, learning_rate = 1e-3, weight_decay = 1e-4, replay_buffer_size = 20 000
